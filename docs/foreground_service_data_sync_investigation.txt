Foreground Service DATA_SYNC Permission Investigation
======================================================

A. Permission source
--------------------
The permission android.permission.FOREGROUND_SERVICE_DATA_SYNC is declared
directly in the app's main Android manifest, not introduced by any dependency.

Exact file:
  /home/user/myapp/android/app/src/main/AndroidManifest.xml:12

Snippet:
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />

The manifest merger report explicitly traces it to only this origin:
  uses-permission#android.permission.FOREGROUND_SERVICE_DATA_SYNC
  ADDED from /home/user/myapp/android/app/src/main/AndroidManifest.xml:12:5-87
      android:name
          ADDED from /home/user/myapp/android/app/src/main/AndroidManifest.xml:12:22-84

No inspected dependency declares this permission:
  - androidx.work:work-runtime:2.10.2 only adds FOREGROUND_SERVICE
  - flutter_local_notifications manifest adds only VIBRATE and POST_NOTIFICATIONS
  - firebase_auth, billing, revenuecat, supabase_flutter and others do not declare it


B. Actual usage
---------------
No.

No <service> in the merged manifest declares android:foregroundServiceType="dataSync".

The only foreground-service-related component in the merged manifest is
androidx.work.impl.foreground.SystemForegroundService from work-runtime, and
it has no foregroundServiceType attribute.

The Dart code uses:
  - workmanager ^0.9.0+3
  - flutter_local_notifications ^20.1.0

Neither code path configures a foreground service with type dataSync, and
flutter_local_notifications does not declare a dataSync foreground service
in its manifest.

Searches across the codebase for these patterns returned no matches:
  foregroundServiceType, startForegroundService, ForegroundService,
  startForeground, stopForeground, dataSync


C. Is it required?
------------------
No.

The app's functionality does not genuinely require this permission:
  - Bookmarks/links are saved locally.
  - Reminders are scheduled with AlarmManager/WorkManager.
  - Notifications use FlutterLocalNotificationsPlugin.
  - WorkManager tasks use the generic FOREGROUND_SERVICE permission only.
  - Firebase Auth, Supabase, RevenueCat, and short API requests do not use a
    dataSync foreground service.

The dataSync foreground service type is intended for long-running data
synchronization operations. This app has no such component.


D. Safe removal
---------------
Since the permission is app-declared and not introduced by a dependency,
remove it directly from the main manifest.

Exact change in:
  /home/user/myapp/android/app/src/main/AndroidManifest.xml

Remove this line:
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />

The surrounding block should then read:
    <!-- Required for WorkManager / background processing on Android 14+ -->
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    
    <application
        android:label="Bookmark Reminder"

No tools:node="remove" workaround is necessary because no dependency adds
this permission.


E. Risks
--------
Removing the permission should not break existing functionality.

Why:
  - WorkManager continues to operate with the base FOREGROUND_SERVICE permission.
  - Notifications, Firebase Auth, Supabase, RevenueCat, and all other features
    do not depend on this permission.
  - No code path currently uses a dataSync foreground service.

Residual risk is limited to future development that may introduce a foreground
service with foregroundServiceType="dataSync". In that case, the permission
would need to be re-added.
